# 常态化制作流程

每期视频建立独立工作目录；本仓库保留流程，单期项目保存实际作品。可以把项目放在 `episodes/<slug>/`，并把大文件排除在 Git 之外。

| 阶段 | 负责人/工具 | 最小产物 | 通过关卡 |
| --- | --- | --- | --- |
| 0. 定义 | 制作者 | 选题简报 | 主题、受众、核心问题、时长、语言和交付形式明确 |
| 1. 调研 | Anything to Explainer Production | `research.md` | 每条上画面的事实有来源；未核实内容标为待核 |
| 2. 文案 | Anything to Explainer Production | `narration.txt`、章节名 | **先审文案**：故事主线、事实、章界、字数和预估时长通过 |
| 3. 分镜 | Anything to Explainer Production | `storyboard.md`、图解任务单 | 每镜头有主角、持续动作、停留时间、字幕安全区和来源 |
| 4. 图解 | Anatomy（需要时） | 源码、导出图、图解说明 | 机制与读数真实；细节和层级可读；运动状态可复现 |
| 5. 配音与时间轴 | Anything to Explainer Production | 音频、字幕、帧时间轴 | **先审声音**：发音和节奏通过；字幕与配音对齐 |
| 6. 合成 | Remotion | 可运行的项目与 Studio 预览 | 前 30 秒的风格、字号、语速和节奏先通过，再做全片 |
| 7. 质检 | 三工具各自的检查 + 人工通看 | QC 记录、成片 | 事实、画面、字幕、声音、连续性和导出参数通过 |
| 8. 复盘 | 制作者与贡献者 | `episode-review.md`、流程改动 | 问题有证据、改法可验证、下次能复用 |

## 每期的工作顺序

### 0. 建立简报

填写 [`templates/episode-brief.md`](../templates/episode-brief.md)。先确定“观众看完能解释什么”，再选素材与图解。时长、语言和配音来源需在正式写文案前确定。

### 1. 调研与文案

按 Anything to Explainer Production 的研究规范收集可靠出处。每个数字、术语和人名都能回指 URL 或明确的原始资料。解说词维持一个贯穿例子；章节标题要能直接说明本章内容。交给他人审阅文案，再开始配音和锁帧。

### 2. 分镜与图解选型

镜头按画面单元切分，不机械地一句一镜。每镜头写：配音段落、画面主角、动作、时长、字幕安全区、需要核对的事实。遇到“内部如何工作”的关键机制，再给 Anatomy 写图解任务单；输出要能转为确定的 SVG 或帧序列。制作图解前可先用简图确认解释逻辑，正式图解再按 Anatomy 的部件、层级、运动和验证规范完成。

### 3. 配音、合成与预览

选择配音方式，生成音频和字幕时间轴。Remotion 项目只使用一个帧率和一套章节时间点。先打开 Studio 看前 30 秒，再检查全片；修改文案或语速后重建时间轴，不能只挪字幕掩盖错位。

### 4. 质检与归档

按下表检查，并填写 [`templates/episode-review.md`](../templates/episode-review.md)。质检问题分为阻断交付、可修复的小问题和已接受的限制。把结论链接回分镜或时间轴，方便下次定位。

| 检查项 | 判定方法 |
| --- | --- |
| 事实 | 逐项核对研究记录；示意数据明确标“示意” |
| 声音与字幕 | 听看全片，检查漏字、错字、发音、字幕同步及遮挡 |
| 画面 | 一个主要视觉焦点；图解读数与动作一致；图解与字幕不互相压住 |
| 节奏 | 重点入场有时间理解；画面动作服务解说；章节衔接有承接 |
| 连续性 | 镜头交界无空帧、突变和声音断裂 |
| 导出 | 实际文件能播放；分辨率、帧率、时长和音量符合简报 |

## 改进循环

每次只把**已在实际项目中验证**的规则写回主流程。新建议先在贡献记录里说明：原问题、发生在哪个镜头或阶段、改动、前后证据、适用边界。下期再用同一检查项确认改动是否有效。
